# 01. Бизнес-анализ

Продукт: цифровой инструмент диагностики и ведения пациентов с тревогой и депрессией
Соревнование: кейс-чемпионат «Клинический компас 2026» (Авинейро / ГК «ХимРар» · НМИЦ ПН им. Сербского · Сеченовский Университет)
Статус: черновик для команды (внутренний), v0.1, 2026-10-09

---

## 1. Контекст

- **Задача чемпионата**: за 2 недели (15–30.10) сделать работающий прототип цифрового инструмента для **диагностики и ведения** пациентов с тревогой и депрессией. Один общий кейс, язык — русский.
- **Жюри и бенефициары**: психиатрический центр (Сербский), медвуз (Сеченов), фарм-индустрия (Авинейро, производитель оригинального анксиолитика АВИАНДР®/маритупирдин при ГТР).
- **Точные метрики оценки известны только 15–16.10** (объявляются на открытии, публикуются в чате; после публикации неизменны). Стратегия: модульный MVP, акценты подгоняем под официальные метрики после 15.10.
- Демо-день 30.10: питч + постерная сессия (зрительское голосование = отдельный приз). Предзащита 28.10 → топ-3.

## 2. Целевая проблема (для питча)

> Пациент с тревогой/депрессией наблюдается у врача эпизодически: между визитами состояние никто не отслеживает. Диагностика субъективна и зависит от одной встречи; рецидивы и риск-эскалации (вплоть до суицидальных мыслей) выявляются поздно. У врача нет структурированных данных динамики, есть только устные «похуже/получше».

Продукт закрывает разрыв между визитами: **структурированный скрининг + мониторинг + передача врачу**, а не «ещё один чат-бот».

## 3. Стейкхолдеры и их интересы

| Стейкхолдер | Интерес | Что это значит для продукта |
|---|---|---|
| Пациент (18+ с тревогой/депрессией, лёгкая–средняя тяжесть) | понять состояние, не чувствовать себя один на один с проблемой, безопасность (не «залатать» суицидальный риск болтовнёй) | короткие ежедневные чек-ины, понятные тренды, явная эскалация к помощи |
| Врач (психиатр/психотерапевт, ординатор) | видеть динамику между визитами, не утонуть в данных, получить обоснование для решения | дашборд рисков и траекторий, правила триажа, экспорт «выписки» |
| Медучреждение (поликлиника/диспансер) | снизить нагрузку на приём, повысить приверженность, соответствие 152-ФЗ | инструмент без врачебного диагноза «на автомате», аудит доступа |
| Авинейро (индустриальный партнёр) | цифровой контур вокруг терапии (в т.ч. АВИАНДР), переиспользуемое ядро; IP победителя переходит им | SDK-архитектура: клинический движок отделён от UI |
| Сербский / Сеченов (жюри) | клиническая достоверность, безопасность, научная база | валидированные шкалы, правила эскалации, позиционирование «скрининг + decision support», не «бот ставит диагноз» |

## 4. Позиционирование и КРАСНЫЕ ЛИНИИ

Позиционирование: **дополняющий (adjunct) инструмент скрининга и мониторинга; финальное решение принимает врач**.

- НЕ «автоматическая постановка диагноза» (в РФ диагноз — врачебная функция, 323-ФЗ; для жюри-психиатров это главный красный флаг).
- НЕ назначение/коррекция терапии без врача (телемедицина — 242-ФЗ: только врач, после очного приёма).
- НЕ хранение биометрии (голос) без отдельного согласия (152-ФЗ ст. 11): аудио обрабатываем на лету и удаляем.
- НЕ «чат-бот, который лечит»: чат — слой общения и поддержки, а не ядро.

## 5. Функциональный скоуп MVP (2 недели)

**Входит (ядро):**
- F1. Каталог валидированных шкал: PHQ-9, GAD-7, HADS (A/D), идентификация тревоги/депрессии.
- F2. Скрининг: заполнение шкалы → расчёт балла → интерпретация + триаж-уровень (зелёный/жёлтый/красный) по клиническим порогам.
- F3. Эскалация безопасности: флаг суицидального риска (п.9 PHQ-9 / п.8 GAD-7-нет…) → немедленное уведомление, контакты горячей линии (112 / псих. помощь), уведомление врача.
- F4. Мониторинг: ежедневные чек-ины (генерация коротких анкет из заполненной шкалы), тренды баллов во времени.
- F5. Врачебная панель: список пациентов по уровню риска, график динамики, история заполнений.
- F6. Дневник самочувствия: заметки, настроение, сон (свободные поля + теги).
- F7. Чат-поддержка: FAQ/горячая линия, эмпатичные скрипты (rule-based; LLM опционально).
- F8. Согласие на обработку ПДн (152-ФЗ) и аудит доступа.

**Входит как отличие «инструмента ведения» от «бота»:** врач-дашборд, эскалация, тренды.

**Отложено/полировка:** TTS-голос (после F1–F8), мобильные push, интеграция ЕГИСЗ/МИС, ML-модели «цифровых биомаркеров» (в питче — как дорожная карта, не как MVP).

## 7. Критерии успеха

- **Соревновательные**: проход предзащиты 28.10 (топ-3), высокая сумма баллов метрик 30.10; сильное выступление на постерной сессии.
- **Продуктовые (измеримые в демо)**: скрининг 3 шкал за < 3 мин; пороги триажа совпадают с официальными; эскалация красного риска срабатывает < 1 c после ответа; врач видит динамику пациента за 1 экран.
- **Качественные (демо-нагрузка)**: прототип кликается жюри без багов; демо-данные выглядят правдоподобно (симулятор пациентов).
