### 1.1. Статус проверки источников (20.10.2026)

| # | Статус | Как формулировать в презентации |
|---|---|---|
| 1 | ✅ ссылка проверена: JMIR e60435, Limbic Access, 244 пациента, 5 NHS-сервисов | только как **аналогия** междусессионной ИИ-поддержки; Limbic Access — не наш продукт и не валидация нашего чек-ина |
| 2 | ✅ ссылка проверена: Frontiers in Digital Health, DOI 10.3389/fdgth.2026.1755085, N=131 | можно ссылаться напрямую |
| 3 | ⚠️ идентификатор не подтверждён: risksafety.ru/article/521 поиском не находится | до получения DOI/PMID у Дианочки — «данные Фармаконадзора РФ 2019–2024» без точной ссылки |
| 4–7 | ⚠️ указаны только порталы (cris.unibo, bath/elsevierpure, nchr) | запросить DOI/PMID; без них на слайде — без ссылки |
| 8–9 | ⚠️ не проверены | HCL-32 — конкретные PubMed ID (2014/2019), Bauer 2018 — DOI |

Правило: цифра на слайде появляется только со ссылкой, проверенной хотя бы до
уровня DOI/PMID. Непроверенная ссылка — повод убрать цифру, а не поставить
«примерно».
Цитата в слайды — через `title` + `guideline_id` из ответа ассистента:
публичная схема цитаты — `guideline_id`, `title`, `topic` (поля
`year`/`design`/`source_url` из неё убраны, см. коммит `5ffa299`).
Провенанс статей (год, дизайн, URL) живёт здесь, в docs/13 §5 и в комментарии
`api/app/kb_seed.py`.

## 3. Пайплайны

- `bench/ner/` — уже есть: NER-валидация деперсонализации (docs/12);
  расширяется русскими клиническими кейсами ФИО (не датасетами выше).
- `bench/` (build_dataset/run_bench) — гибридный поиск; расширяется
  статьями из docs/13 как eval-запросами («найди статью про вортиоксетин»).
- Новое — `bench/hdrs/`: прототип HDRS-компаньона (RealCBT/CUEMPATHY →
  извлечение пунктов HDRS → review врача). План, не обязательство на 20.10.
