# Деперсонализация перед LLM (docs/12)

## Задача

Перед любым обращением к LLM API из текста убираются персональные данные:
ФИО, адреса, номера документов, телефоны, email. LLM в проекте — за SPI
(docs/03 §1.3); границей наружу является агент врача (`/assistant/ask`),
поэтому деперсонализация применяется именно там: и к запросу врача, и к
контексту пациента (@-упоминание). С включённым `CC_ASSISTANT_LLM_URL` LLM
(локальный, docs/08 §9) получает ТОЛЬКО очищенный запрос и выбирает раздел
БЗ тулзой `search_<раздел>` (docs/04 FR-17); контекст пациента в LLM не
уходит никогда — роутинг не нуждается в ПДн.

Правовая база: 152-ФЗ ст.3 п.9 (обезличивание), приказ Роскомнадзора №996
(методы обезличивания). Применяемый метод — **замена** (категорийные
плейсхолдеры), режим **redact** — сокращение.

## Границы

- Деперсонализуется ВХОД LLM-gateway (запрос + карта пациента), до любого
  сетевого вызова. Ответ наружу (врачу) приходит уже с плейсхолдерами.
- Внутри системы ПДн видны как раньше: деперсонализация — это граница
  исходящего, не доступ.
- Не деперсонализуется: числовые поля карты (баллы шкал, триаж, тренд) —
  это не ПДн, а клиническая динамика, нужная LLM для ответа.

## Что маскируется (core/compass/depersonalize.py)

| Категория | Примеры | Способ |
|---|---|---|
| ФИО | «Иванов Иван Иванович», «Иванов И.И.», «Иванова…» (падежи) | deny-list из ростра врача + основа с флексией |
| Адрес | «г. Москва, ул. Ленина, д. 5, кв. 10», «проспект Мира, 23» | опорные слова ул./просп./г./обл. + дом/квартира |
| Документы | СНИЛС 123-456-789 01, ИНН (10/12), ОМС (16), паспорт «4509 123456» | жёсткие цифровые формы |
| Дата рождения | «дата рождения 12.03.1954», «д.р. 12.03.1954» | только с явным маркером; дата без маркера (приём, начало симптомов) не маскируется |
| Телефон | +7 999 123-45-67, 8 900 123 45 67 | РФ-формат |
| Email | doctor@clinic.org, иванов@демо.рф | в т.ч. кириллический local-part |

ФИО-детекция: по умолчанию — deny-list пациентов из ростра врача (система
знает, кто её пациенты); NER-эвристики в чистом regex-пути не применяются —
дают ложные срабатывания на официальные названия («Министерство
Здравоохранения РФ»).

## NER (опционально)

Сверх deny-list работает нейросетевая детекция ФИО. Два backend'а на выбор
(бенчмарк и цифры — `bench/ner/README.md`):

| backend | модель | лицензия | FIO F1 (exact/overlap) |
|---|---|---|---|
| `natasha` | NewsNERTagger (slovnet news v1) | MIT | 0.168 / 0.456 |
| `rubert` | redmadrobot-rnd/rubert-base-pii-ner (ruBert-base) | Apache-2.0 | **0.933 / 0.947** |

Измерено на публичном `redmadrobot-rnd/pii_benchmark` (MIT, 2841 строка).
`rubert` в 5.5x точнее по ФИО; полный гвард (regex ∪ rubert) даёт лучший
суммарный F1 (0.493 exact / 0.637 overlap). Включение — два условия:

1. `pip install -e "api[ner-rubert]"` (torch+transformers) или `api[ner]` (natasha);
   в рантайм-образ Docker extra не входит — только по запросу;
2. `CC_DEPERSONALIZE_NER=rubert` (или `natasha`; `true` = natasha для обратной
   совместимости, `off` — по умолчанию). Модель rubert переопределяется
   `CC_NER_MODEL` (по умолчанию `redmadrobot-rnd/rubert-base-pii-ner`).

Без выполнения любого из условий путь — чистый regex/deny-list (детерминизм
демо). При флаге on, но отсутствующей/нерабочей библиотеке — лог + деградация
до regex-пути, запросы не падают.

Архитектура: `api/app/services/depersonalize.py` — SPI
`NameExtractor.extract(text)` / `extract_spans(text)` (имена для доливки в
deny-list): `NullNameExtractor` (по умолчанию), `NatashaNameExtractor` и
`RubertPiiNameExtractor` (ленивый импорт, конвейер строится один раз на процесс,
при отсутствии зависимостей/модели — лог + деградация до regex).
`scrub_for_llm` при флаге прогоняет NER по запросу, ФИО и дневнику карты и
добавляет найденные имена в deny-list — дальнейшее маскирование падежных форм
делает чистая функция ядра (основа + флексия).

## Контракт

```python
# core/compass/depersonalize.py — чистая функция, без I/O
@dataclass(frozen=True)
class Finding:      # kind: FIO|ADDRESS|DOC|PHONE|EMAIL; start/end; original
@dataclass(frozen=True)
class Depersonalized:
    text: str          # с плейсхолдерами [ФИО]/[АДРЕС]/[ДОКУМЕНТ]/[ТЕЛЕФОН]/[EMAIL]
    findings: tuple[Finding, ...]

depersonalize(text, names=None, *, mode="replace"|"redact") -> Depersonalized
```

Идемпотентность: плейсхолдеры повторно не матчатся. Пересечения: при равном
старте побеждает более длинное совпадение (email «иванов@mail.ru» целиком, а
не ФИО-локальная часть), затем приоритет категории (ФИО важнее адреса
«ул. Иванова»).

## Применение (api/app/services/agent.py, routers/assistant.py)

```python
names = services.clinician.roster_names(db, user.id)   # deny-list: ФИО пациентов врача
query, patient_ctx, report = services.agent.scrub_for_llm(body.query, patient_ctx, names)
result = _agent_factory().invoke(query, ..., patient_context=patient_ctx)
```

В `report` — только категории и количество (`{"masked": {"FIO": 2, ...}}`),
исходные значения наружу не возвращаются. Отчёт кладётся в тело ответа
(`depersonalization`) — демо-прозрачность работы guard-а.

### Факт-чек зависимостей (сетевой обмен)

Проверено, что путь деперсонализации **не отправляет текст никуда**:

- **pymorphy2** — морфологический анализатор на локальном словаре OpenCorpora
  (`pymorphy2-dicts-ru`). В коде пакета **нет ни одного** сетевого вызова
  (grep: ни `requests`, ни `urllib`, ни `socket`, ни `http`). Утверждение
  «pymorphy2 шлёт строки в сервис Яндекса» — неверно; это путаница с
  **mystem** (отдельный CLI-анализатор Яндекса) или Yandex Speller API.
- **natasha** — модели (`navec`-эмбеддинги и `slovnet`-NER) **упакованы в
  wheel** (`natasha/data/emb`, `natasha/data/model`), скачивания в рантайме
  нет. Единственные URL Яндекса (`storage.yandexcloud.net`) — в **обучающих**
  утилитах (`navec/train/s3.py`, `slovnet/s3.py`), которые в инференсе не
  импортируются (boto3 даже не установлен).
- **Доказательство**: NER-инференс прогнан с жёстко заблокированными
  `socket.socket`/`create_connection`/`getaddrinfo` — работает, ноль попыток
  выхода в сеть. То же закреплено тестом
  `test_no_network_egress_on_scrub_path`.

**Но pymorphy2 действительно старый**: 0.9.1 (2018), не поддерживается,
на Python ≥3.11 падает (`inspect.getargspec` удалён), а `pkg_resources`
удалён из setuptools ≥81. Поэтому:

- `MorphVocab` (нормализация спана) в нашем адаптере **опционален** —
  конструируется в `try/except`, при сбое маскируется исходное написание;
  на Python 3.14 нормализация не работает, и это не влияет на маскирование;
- сам `import natasha` требует pymorphy2 только как модуль (импорт класса),
  не как рабочий анализатор — поэтому NER работает даже при сломанном
  словаре;
- pymorphy3 (поддерживаемый форк) не даёт алиаса `pymorphy2`, поэтому
  подменить прозрачно нельзя — оставляем как есть, с деградацией.

## Тесты

- core/tests/test_depersonalize.py (13): все сущности, падежные формы, режим
  redact, идемпотентность, отсутствие ложных срабатываний на клиническом
  тексте («по 5 мг дважды в день», «д. 5 в таблице») и официальных названиях.
- api/tests/test_assistant.py — граница LLM: ФИО/контент дневника не
  появляются в теле ответа даже в падежных формах; отчёт присутствует.
- api/tests/test_depersonalize_ner.py (5): флаг off → Null; флаг on без natasha
  → деградация без падения; фейковый natasha-модуль (PER-спаны) → имена; NER-
  имена доливаются в deny-list и маскируются; флаг off не вызывает NER.
  Проверено и на реальном natasha (Python 3.14: MorphVocab/pymorphy2 не
  грузится — нормализация опциональна, маскируется исходное написание).
