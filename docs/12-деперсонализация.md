# Деперсонализация перед LLM (docs/12)

## Задача

Перед любым обращением к LLM API из текста убираются персональные данные:
ФИО, адреса, номера документов, телефоны, email, дата рождения. LLM в проекте —
за SPI (docs/03 §1.3); границами наружу являются агент врача
(`/assistant/ask`, `/assistant/threads`), анализ переписки (FR-31,
`chat_insights`) и redline-пути агента. С включённым `CC_ASSISTANT_LLM_URL`
(локальный, docs/08 §9 или внешний шлюз) LLM получает ТОЛЬКО очищенный текст.

Правовая база: 152-ФЗ ст.3 п.9 (обезличивание), приказ Роскомнадзора №996
(методы обезличивания). Применяемый метод — **замена** (категорийные
плейсхолдеры), режим **redact** — сокращение.

## Границы

- Деперсонализуется ВХОД LLM-gateway (запрос + карта пациента + лента
  сообщений), до любого сетевого вызова. Ответ наружу (врачу) приходит уже с
  плейсхолдерами.
- Внутри системы ПДн видны как раньше: деперсонализация — это граница
  исходящего, не доступ.
- Не деперсонализируется: числовые поля карты (баллы шкал, триаж, тренд) —
  это не ПДн, а клиническая динамика, нужная LLM для ответа. Отдельно взятый
  возраст («64 года») — клинические данные; в связке с ФИО в той же фразе
  возраст маскируется как комбо-идентификатор.
- В FR-31 в LLM уходят только реплики **пациента** (`sender == "PATIENT"`);
  ответы помощника/врача — шум, который провоцирует выдуманные факты
  (замер: шумная лента → 0 фактов, только пациент → 4 факта).

## Что маскируется (core/compass/depersonalize.py)

| Категория | Примеры | Способ |
|---|---|---|
| ФИО | «Иванов Иван Иванович», «Иванов И.И.», «Сидорову Петру» | deny-list ростра (основа+флексия) ∪ NER-спаны (rubert/hybrid) |
| Адрес | «г. Москва, ул. Арбат, д. 21, кв. 8», «Санкт-Петербург, Лиговский пр-т, д. 55» | опорные слова + расширение влево на город/область |
| СНИЛС | `123-456-789 01`, `11223344595` | формат с разделителями — безусловно; слитно — контрольное число/маркер |
| ИНН | 10/12 цифр | контрольные числа; маркер «ИНН» страхует опечатки |
| ОМС | `1234 5678 9012 3456`, 16 цифр слитно | контрольная цифра; формат с пробелами — безусловно |
| Паспорт | `4509 123456`, `4509123456` | серия 4 + номер 6 (с пробелом/№/маркером «паспорт») |
| Медкарта/ИБ | «Медкарта № 456123», «ИБ 45678/2024», «история болезни 987654» | маркер + номер (в т.ч. `77-004521`) |
| Дата рождения | `12.03.1954`, `12-03-54`, `1985-04-17`, `9 августа 1949`, `12.03.1954 г.р.` | только с маркером (дата рождения/д.р./род./родился/г.р.); клиническая дата без маркера не маскируется |
| Телефон | `+7 926 123-45-67`, `8 (926) 123-45-67`, `89261234567`, `926 123-45-67`, `9261234567` | 11 цифр 7/8… или 10-значный мобильный 9…; нормализация к E.164 |
| Email | doctor@clinic.org, иванов@демо.рф | в т.ч. кириллический local-part |
| Возраст | «Петрова Анна, 64 года» | только при ФИО в той же фразе (≤60 символов, без разрыва предложения) |

Маскирование **span-based**: все кандидаты (структурные правила, NER,
deny-list) объединяются как `(вид, start, end)`, пересечения разрешаются
детерминированно (старт → длиннее → приоритет категории), соседние спаны
одного вида склеиваются (NER режет «Иванов Пётр» + «Сергеевич»). `Finding`
несёт `kind` (для плейсхолдера) и `category` (SNILS/INN/OMS/PASSPORT/MEDCARD —
для отчёта и бенчмарка).

ФИО-детекция: по умолчанию — deny-list пациентов из ростра врача; NER
подключается флагом (ниже). В чистом regex-пути NER-эвристик нет — они дают
ложные срабатывания на официальные названия.

## Backend'ы (CC_DEPERSONALIZE_NER)

| backend | что это | когда |
|---|---|---|
| `off` (default) | только структурные правила + deny-list | демо, тесты, офлайн |
| `natasha` | NewsNERTagger, PER→ФИО, LOC→адрес, лёгкий | малый образ без torch |
| `rubert` | redmadrobot-rnd/rubert-base-pii-ner (Apache-2.0) | ФИО/адреса моделью, документы — правилами |
| `hybrid` | rubert (только ФИО/адрес, с отсевом мусорных однословных) + структурные правила + валидаторы | **прод-путь** |

`true`/`1` = natasha (обратная совместимость). Модель переопределяется
`CC_NER_MODEL`. Зависимости — опциональные extra `api[ner]` / `api[ner-rubert]`
(torch+transformers), ленивый импорт: `uv sync` без extra и docker-сборка не
ломаются.

### Метрики на клиническом корпусе

`bench/ner/clinical_contexts/` — 332 синтетических контекста четырёх форм
egress-пути (чат пациента, дневник/чек-ин, вопрос врача, батч FR-31),
gold-спаны по конструкции. Оценка — entity-level precision/recall, совпадение
= пересечение ≥50% длины более короткого спана (маскирование посимвольное).

| stack | micro P | micro R | FIO R | DOC-категории R | ADDRESS R | DOB R | AGE R |
|---|---|---|---|---|---|---|---|
| regex (правила ядра) | 1.000 | 0.344 | 0.000 | 0.750–1.000 | 1.000 | 1.000 | 0.000 |
| rubert (модель без правил) | 0.409 | 0.753 | 1.000 | 0.850–1.000 | 1.000 | 0.000 | 0.000 |
| hybrid (прод) | **1.000** | **0.987** | 0.975 | 1.000 | 1.000 | 1.000 | 1.000 |
| gliner_multi_pii-v1 | см. REPORT-pii.md | | | | | | |
| LLM (home-stable, батчи) | см. REPORT-pii.md | | | | | | |

Остаточный промах hybrid — 8/320 ФИО, записанных целиком строчными буквами
(«сидорова галина»): rubert их не размечает. Осознанно не лечим эвристикой по
шаблону фразы — это дало бы ложные срабатывания на клиническом тексте;
2.5% ФИО при recall ≥0.98 принято как остаточный риск (docs/10).

Публичный `redmadrobot-rnd/pii_benchmark` (MIT, 2841 строка, 22 категории)
остаётся вторичной проверкой сопоставимости (`bench/ner/run_ner_bench.py`):
полный гвард (regex ∪ rubert) — 0.489 exact / 0.631 overlap (до ужесточения
валидаторов было 0.493/0.637 — разница в пределах шума; FIO rubert стабильно
0.933/0.947). Категории вне нашего egress-скоупа (деньги, URL, события) в
этот F1 входят и тянут его вниз — поэтому основной метрикой стал клинический
корпус.

### GPU/латентность

rubert-base на RTX 5090 (batch=1, `aggregation_strategy=first`): ~40 мс на
контекст, модель грузится один раз на процесс (~2 с с диска, ~1.5 ГБ).
Инференс синхронный; вызывается из egress-пути до HTTP к LLM.

## Fail-closed (prod)

`CC_PROD_MODE=true` + настроенный LLM-egress (`CC_ASSISTANT_LLM_URL` или
`CC_CHAT_INSIGHTS_ENABLED`) требует ML-backend: `CC_DEPERSONALIZE_NER=hybrid`
(или rubert/natasha) — иначе `Settings()` падает на старте. Если модель/зависи-
мость не загрузилась или инференс упал, `scrub_text` поднимает
`DepersonalizationUnavailable` → **503 `DEPERSONALIZATION_UNAVAILABLE`**;
сырой текст в LLM не уходит. Вне prod сохраняется деградация до regex с
предупреждением в лог.

## Контракт

```python
# core/compass/depersonalize.py — чистая функция, без I/O
@dataclass(frozen=True)
class Span:      # kind: FIO|ADDRESS|DOC|DOB|PHONE|EMAIL|AGE; start/end; category
@dataclass(frozen=True)
class Finding:   # kind, start/end, original, category (SNILS/INN/OMS/PASSPORT/MEDCARD)
@dataclass(frozen=True)
class Depersonalized:
    text: str      # [ФИО]/[АДРЕС]/[ДОКУМЕНТ]/[ДАТА РОЖДЕНИЯ]/[ТЕЛЕФОН]/[EMAIL]/[ВОЗРАСТ]
    findings: tuple[Finding, ...]

depersonalize(text, names=None, *, mode="replace"|"redact", extra_spans=()) -> Depersonalized
extract_spans(text, names=None, *, extra_spans=()) -> list[Span]
# api/app/services/depersonalize.py — единая точка для egress
scrub_text(text, names=None) -> Depersonalized
```

Идемпотентность: плейсхолдеры повторно не матчатся. Пересечения: при равном
старте побеждает более длинное совпадение (email «иванов@mail.ru» целиком, а
не ФИО-локальная часть), затем приоритет категории (ФИО важнее адреса
«ул. Иванова»).

## Применение (api/app/services/agent.py, chat_insights.py, routers/assistant.py)

```python
names = services.clinician.roster_names(db, user.id)   # deny-list: ФИО пациентов врача
query, patient_ctx, report = services.agent.scrub_for_llm(body.query, patient_ctx, names)
result = _agent_factory().invoke(query, ..., patient_context=patient_ctx)
```

В `report` — только категории и количество (`{"masked": {"FIO": 2, ...}}`),
исходные значения наружу не возвращаются. Отчёт кладётся в тело ответа
(`depersonalization`) — демо-прозрачность работы guard-а.

### Факт-чек зависимостей (сетевой обмен)

Проверено, что путь деперсонализации **не отправляет текст никуда**:

- **pymorphy2** — морфологический анализатор на локальном словаре OpenCorpora
  (`pymorphy2-dicts-ru`). В коде пакета **нет ни одного** сетевого вызова
  (grep: ни `requests`, ни `urllib`, ни `socket`, ни `http`). Утверждение
  «pymorphy2 шлёт строки в сервис Яндекса» — неверно; это путаница с
  **mystem** (отдельный CLI-анализатор Яндекса) или Yandex Speller API.
- **natasha** — модели (`navec`-эмбеддинги и `slovnet`-NER) **упакованы в
  wheel**, скачивания в рантайме нет. URL Яндекса — только в обучающих
  утилитах, которые в инференсе не импортируются.
- **rubert** — веса из локального HF-кэша (`CC_NER_MODEL`), загрузка один раз
  на процесс; после прогрева сеть не нужна.
- **Доказательство**: NER-инференс прогнан с жёстко заблокированными
  `socket.socket`/`create_connection`/`getaddrinfo` — ноль попыток выхода.
  Закреплено тестом `test_no_network_egress_on_scrub_path`.

**pymorphy2 старый** (0.9.1, 2018): на Python ≥3.11 падает, `pkg_resources`
удалён из setuptools ≥81. Поэтому `MorphVocab` в адаптере **опционален** —
конструируется в `try/except`, при сбое маскируется исходное написание.
natasha остаётся только для лёгких установок; прод-путь — `hybrid` на rubert.
