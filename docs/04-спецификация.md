> Нормализация телефона FR-22 строгая: принимаются только ASCII-цифры (не-ASCII цифры — 422 `PHONE_INVALID`), `+` допускается исключительно в полном `+7XXXXXXXXXX`, без ведущего `+` — 10 цифр (`9XXXXXXXXX` → `+7…`) или 11 цифр с `7`/`8`; усечённый `+7926123456` не нормализуется, а отклоняется.

## 2. Нефункциональные требования

| ID | Требование | Значение |
|---|---|---|
| NFR-1 | Производительность API | p95 < 300 мс на L2×5 (~150 RPS пик) для `GET`/`POST /screenings`, `POST /runs/{id}/finish`, `GET /clinician/patients`; эскалация RED < 1 с после `finish`. ### 3.3 Коды ошибок

`VALIDATION` (422), `UNAUTHORIZED/TOKEN_EXPIRED` (401), `FORBIDDEN/NO_ROSTER/ROLE_MISMATCH` (403), `CONSENT_REQUIRED` (403), `NOT_FOUND` (404), `CONFLICT/RUN_CLOSED/RUN_ALREADY_TODAY` (409), `TOO_MANY_REQUESTS` (429), `EMIAS_DISABLED/EMIAS_MISCONFIGURED` (503), `EMIAS_NOT_LINKED/EMIAS_PATIENT_NOT_FOUND/EMIAS_BAD_SNILS` (404/422), `EMIAS_AMBIGUOUS_PATIENT/EMIAS_SNILS_MISMATCH/EMIAS_ALREADY_LINKED` (409), `EMIAS_PATIENT_REQUIRED` (422), `EMIAS_UPSTREAM` (502).

Чек-ин (docs/16 §4): `CHECKIN_INCOMPLETE` (422, не все пункты шага), `CHECKIN_UNKNOWN_ITEM` (422, неизвестный или не предъявленный на шаге пункт), `CHECKIN_OUT_OF_RANGE` (422, значение вне `0..max_value`/не целое/bool), `CHECKIN_NOT_FOUND` (404, чужой или отсутствующий сеанс), `CHECKIN_ALREADY_DONE` (409, день уже завершён), `CHECKIN_BUSY` (409, конфликт параллельного старта — повторить).

## 4. Телеметрия эскалации (лог обязателен)

Пациент завершил скрининг → в той же транзакции: (1) расчёт assessment, (2) если RED/суицид → `escalation` (kind SUICIDAL|SEVERE) + пациенту в ответ контакты помощи, (3) запись в `audit_log`. Уведомление врачу — внутрисистемное: новая карточка escalation в панели врача (push/email/SMS вне MVP). Целевой срок `<1 с` — от `POST /runs/{id}/finish` до коммита транзакции. Нарушение целостности этой последовательности — блокирующий дефект (см. 06).

Чек-ин (docs/16 §3): HR4 = «Да» → `escalation` (`kind=CHECKIN_RISK`, `checkin_session_id`, без assessment) создаётся в той же транзакции, что и шаг ядра, вместе с `Notification` ростерным врачам; итоговый `signal` обновляет ту же строку до `CHECKIN_RISK_URGENT` и уведомляет повторно (не более одной эскалации на сеанс — partial unique index). `notified_clinician_at` — только если уведомления реально созданы. Сигнал без ростера виден в общей очереди `GET /escalations` (врач/админ, аудит `READ_ESCALATIONS`), поэтому не теряется; срок реакции этой очередью не гарантируется.

## 5. Схемы данных (Postgres, DDL-эскиз)

> **Источник истины по схеме — Alembic-миграции** (`api/alembic/versions/`), а не этот эскиз. `db.init_db()` выполняет `alembic upgrade head`; `Base.metadata.create_all` не используется (он не альтерирует существующие таблицы, из-за чего демо-БД накопила дрейф). Новые поля/индексы — только через `alembic revision --autogenerate -m "..."` + проверку. Эскиз ниже описывает семантику, не точный DDL.

```sql
create table users (
  id uuid primary key default gen_random_uuid(),
  email text unique not null,
  password_hash text not null,            -- argon2id
  role text not null check (role in ('PATIENT','CLINICIAN','ADMIN')),
  fio text,                               -- профиль пациента (см. 02 §6)
  totp_secret text,
  phone bytea,                            -- FR-22: pgp_sym_encrypt (EncryptedText), ПДн
  birth_date date,                        -- FR-22: идентификатор, plaintext (обоснование — 02 §5)
  created_at timestamptz not null default now()
);
-- Профиль пациента: fio на users (см. строку users.fio), roster — отдельная таблица;
-- таблицы profiles нет; ФИО — users.fio, контакты (телефон/дата рождения) — FR-22 на users;
-- пол/прочие атрибуты профиля — только при пилоте (см. 02 §5).
create table consents (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references users(id),
  version int not null, text_hash text not null,
  signed_at timestamptz not null, revoked_at timestamptz
);
create unique index consents_active on consents(user_id) where revoked_at is null;
alter table users add constraint users_totp_role check (role = 'PATIENT' or totp_secret is not null);
-- Каталог шкал (PHQ-9, GAD-7, HADS-A/D) НЕ хранится в БД: единый источник —
-- core/compass/scales.py (см. GET /questionnaires). questionnaire_code — свободный text.
create table runs (
  id uuid primary key default gen_random_uuid(),
  patient_id uuid not null references users(id),
  questionnaire_code text not null,  -- код из каталога ядра (без FK)
  mode text not null check (mode in ('SCREENING','CHECKIN','FOLLOW_UP')),
  started_at timestamptz not null default now(),
  finished_at timestamptz
);
create index runs_patient_online on runs(patient_id, started_at desc);
create unique index runs_screening_open on runs(patient_id) where mode='SCREENING' and finished_at is null;
-- «не чаще 1 чек-ина в календарный день по Москве» обеспечивает
-- checkin_sessions(patient_id, checkin_date) (миграция c6d7e8f9a0b1); прежний
-- runs_checkin_daily удалён.
create table checkin_sessions (
  id uuid primary key default gen_random_uuid(),
  patient_id uuid not null references users(id),
  checkin_date date not null,                       -- день по Москве
  rules_version text not null,                      -- версия правил core/compass/checkin.py
  answers bytea not null,                           -- EncryptedText: pgp_sym_encrypt(JSON)
  presented bytea not null,                         -- шаги, предъявленные пункты, причины модулей
  phase text not null,                              -- core | safety | modules | done
  status text not null check (status in ('in_progress','completed')),
  safety text not null,                             -- none | signal | review | unassessed
  created_at timestamptz not null default now(),
  completed_at timestamptz,
  unique (patient_id, checkin_date)
);
create index ix_checkin_sessions_patient_id on checkin_sessions(patient_id);
create table answers (
  run_id uuid references runs(id) on delete cascade,
  item_key text not null, value int not null,
  answered_at timestamptz not null default now(),
  primary key (run_id, item_key)
);
create table assessments (
  id uuid primary key default gen_random_uuid(),
  run_id uuid unique references runs(id),
  patient_id uuid not null references users(id),
  total_score int not null,
  severity text not null, triage text not null,
  risk_flags jsonb not null default '[]',
  computed_at timestamptz not null default now()
);
create index assessments_patient_time on assessments(patient_id, computed_at desc);
create table escalations (
  id uuid primary key default gen_random_uuid(),
  assessment_id uuid references assessments(id),   -- nullable: источник — чек-ин (docs/16)
  checkin_session_id uuid references checkin_sessions(id),
  notified_clinician_at timestamptz, created_at timestamptz default now(),  -- default заполняет и старые строки временем миграции
  resolved_at timestamptz, resolution bytea                  -- EncryptedText: комментарий разбора
);
create index escalations_patient on escalations(patient_id, resolved_at);
-- не более одной эскалации на сеанс чек-ина (повтор/гонка не создают дубль)
create unique index escalations_checkin_session on escalations(checkin_session_id)
  where checkin_session_id is not null;
-- очередь открытых сигналов: выборка (resolved_at is null) и сортировка по created_at desc (docs/16 §3)
create index escalations_open_queue on escalations(created_at desc)
  where resolved_at is null;
-- история закрытых (GET /escalations?status=resolved) — окно по resolved_at, отдельного индекса нет
create table diary_entries (
  id uuid primary key default gen_random_uuid(),
  patient_id uuid not null references users(id),
  content text not null, mood int check (mood between 0 and 4),
  mood_scale text,                                  -- '0-4' у новых; NULL — историчные 1..10
  sleep_h numeric(4,1), tags jsonb default '[]',
  created_at timestamptz not null default now()
);
create index diary_patient_time on diary_entries(patient_id, created_at desc);
create table chat_messages (
  id uuid primary key default gen_random_uuid(),
  patient_id uuid not null, sender text not null check (sender in ('PATIENT','SYSTEM','CLINICIAN')),
  kind text not null check (kind in ('TEXT','FAQ','HOTLINE','LLM')),
  content text not null, created_at timestamptz not null default now()
);
create table clinician_roster (
  clinician_id uuid references users(id), patient_id uuid references users(id),
  granted_at timestamptz not null default now(), primary key (clinician_id, patient_id)
);
create table push_subscriptions (
  id uuid primary key default gen_random_uuid(), user_id uuid not null references users(id),
  endpoint text not null unique, p256dh text not null, auth text not null,
  created_at timestamptz not null default now()
);
create index push_subscriptions_user on push_subscriptions(user_id);
create table notifications (
  id uuid primary key default gen_random_uuid(), user_id uuid not null references users(id),
  kind text not null check (kind in ('RED_ESCALATION')),
  title text not null, body text not null,
  patient_id uuid references users(id), escalation_id uuid references escalations(id),
  read_at timestamptz, created_at timestamptz not null default now()
);
create index notifications_user on notifications(user_id, created_at desc);
create table device_tokens (
  id uuid primary key default gen_random_uuid(), user_id uuid not null references users(id),
  token text not null unique, platform text not null check (platform in ('android','ios','web')),
  created_at timestamptz not null default now()
);
create index ix_device_tokens_user_id on device_tokens(user_id);
create table fcm_state (
  user_id uuid primary key references users(id),
  last_upgraded_at timestamptz
);
create table audit_log (
  id bigserial primary key,
  actor_id uuid, action text not null, object_type text not null, object_id text,
  ip inet, occurred_at timestamptz not null default now()
);
create index audit_log_occurred on audit_log(occurred_at);
-- append-only: запрет UPDATE/DELETE/TRUNCATE через триггеры на уровне БД
create function forbid_audit_mutation() returns trigger as $$ begin raise exception 'audit_log is append-only'; end $$ language plpgsql;
create trigger trg_audit_no_upd before update or delete on audit_log for each row execute function forbid_audit_mutation();
create trigger trg_audit_no_truncate before truncate on audit_log for each statement execute function forbid_audit_mutation();
-- роли приложения: только INSERT/SELECT на audit_log (REVOKE UPDATE/DELETE/TRUNCATE у сервисной роли)
```

## 6. Демо-сценарий (питч, 5 мин)

1. **Скрининг** за 3 мин: пациент отвечает на GAD-7/PHQ-9 → балл, severity, триаж (зелёный/жёлтый/красный).
2. **Красный флаг**: ответ «да» на суицидальный пункт → мгновенная эскалация (уведомление врачу + контакты помощи).
3. **Врач**: открывает дашборд → пациент в красной зоне → карточка с трендом и выпиской → видит эскалацию. *(Привязка «врач→пациент» предзасеяна симулятором `seed` — иначе панель пуста.)*
4. **Дневник и тренд**: заметки, настроение, сон — динамика на графике за симулированные дни (`seed --days 14` даёт 14 точек тренда; для графика на 30/90 дней запустить `seed --days 90`).
5. **Демонстрация SDD/TDD**: показать, что движок покрыт тестами (это аргумент «безопасной разработки», ГОСТ Р 56939).

## 7. Границы (не входит в MVP)

Автодиагноз (только screening + decision support), назначение/коррекция терапии, регистрация МИ, интеграция ЕГИСЗ/МИС (вопрос жюри — см. 02 §9), push-уведомления, мобильные клиенты.
