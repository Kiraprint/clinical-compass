**Артефакт:** docs/10-модель-угроз.md
**Дата:** 2026-10-19
**Область:** Clinical Compass — цифровой ассистент врача (скрининг тревоги/депрессии)
**Нормативная база:** 152-ФЗ ст.10 (спецкатегория ПДн), ПП РФ №1119 (УЗ-2), ФСТЭК №21, ГОСТ Р 56939-2016, ГОСТ Р ИСО/МЭК 12207-2010, ГОСТ Р ИСО 14971-2011 (менеджмент рисков медицинских изделий), ГОСТ Р МЭК 62304-2013 (ПО медицинских изделий).

## 2. Реестр рисков (ГОСТ Р ИСО 14971-2011)

| ID | Опасность (hazard) | Причина | Последствие | P×S | Митигация | Остаточный риск |
|----|-------------------|---------|-------------|-----|-----------|-----------------|
| R1 | Утечка свободного текста ПДн (дневник/чат/НЯ/приверженность/резолюция/сообщения и заголовки тредов ассистента) | Доступ к БД (dump, backup, консоль) | Раскрытие PHI пациента | 2×5=10 | F1: pgcrypto pgp_sym_encrypt (7 колонок, включая `assistant_threads.title` и `assistant_messages.content` — FR-21); F7: backup gzipped | LOW — числовые баллы plaintext (не free-text) |
| R2 | Кража access-токена через XSS | JS-инъекция в UI | Доступ к ПДн от имени пациента | 2×4=8 | F9: httpOnly cookies (токен недоступен из JS); SameSite=Lax | VERY LOW — токен не в localStorage |
| R3 | Кража refresh-токена | Перехват, XSS, кража устройства | 7-дневный доступ | 2×4=8 | F4: server-side jti, ротация при использовании, /logout; F9: httpOnly cookie | LOW — concurrent race (with_for_update); no family revocation |
| R4 | JWT-форжинг через демо-секрет | Деплой compose as-is в prod | Полный auth bypass | 1×5=5 | F3: inverted fail-fast — демо-секреты запрещены всегда, если не CC_ALLOW_DEMO_SECRETS | VERY LOW — Settings() падает при импорте |
| R5 | Несанкционированный доступ к чужому пациенту (IDOR) | Подмена patient_id в path | Чтение PHI чужого пациента | 2×5=10 | _require_roster на всех patient-scoped endpoints; patient_id из JWT не path | NONE — re-audit подтвердил clean |
| R6 | Отсутствие уничтожения ПДн при отзыве согласия | Consent /revoke только флаг | Нарушение 152-ФЗ ст.9 ч.2-3 | 1×4=4 | F2: DELETE всей спецкатегории + push-токенов | NONE |
| R7 | SQL-инъекция | f-string SQL в seed | Выполнение произвольного SQL | 1×3=3 | F10: parameterized text() bind params | NONE |
| R8 | Утечка PHI в логах/ошибках | pydantic echo input; nginx URI логи | Раскрытие дневника/пароля | 2×2=4 | F5: 422 strip input/ctx; F12: access_log без URI | LOW — application logs могут содержать stack traces |
| R9 | П потеря данных при сбое | Нет backup | Утрата всех ПДн | 1×5=5 | F7: tools/backup.sh (pg_dump gz, 30d retention), restore.sh | LOW — нет автоматического cron в демо |
| R10 | Ложный/пропущенный RED флаг | Ошибка в triage/risk_flags | Суицидальный риск не замечен вовремя | 2×5=10 | Эскалация в транзакции <1s; SUICIDAL_IDEATION → RED всегда; routing REQUIRED | LOW — пороги [TBD: подтвердить медиком] |
| R11 | Несанкционированная диагностика/назначение | LLM выходит за red line | Вред пациенту от авто-диагноза | 1×5=5 | detect_redline: REDLINE_DIAGNOSIS/TREATMENT; 323-ФЗ ст.36.2 red line | VERY LOW — нет LLM в loop (deterministic RAG) |
| R12 | Утечка ключа шифрования | pg_stat_activity во время миграции | Расшифровка всех ПДн | 1×4=4 | NEW-3: одноразовая миграция, maintenance window; runtime: bind param | LOW — ключ в env, не в git |
| R13 | Индексация текста без права использования | автоприём гайдлайнов, у которых лицензия не подтверждена | Нарушение авторских прав ВОЗ/журнала | 1×4=4 | вердикт критерия `license`: скан всего текста (до 400 000 символов, `LICENSE_SCAN_CHARS`) — `CC BY-NC-SA 3.0 IGO` → `met`; `All rights reserved`/`© WHO` → `not_met`, approve заблокирован; + `CC_ENRICH_AUTO_PUBLISH_GUIDELINES` | LOW — 2 гайдлайна ВОЗ остаются кандидатами до письменного разрешения |
| R14 | Отравление КБ недостоверной/нерелевантной публикацией | автоматический приём статей из PubMed | Ответ агента с опорой на мусор | 3×3=9 | статьи только `candidate` → approve ADMIN (Кирилл/Марк); жёсткие критерии (ретракция, тема, свежесть, дизайн) блокируют approve; каждый вердикт несёт цитату-подстроку; ответ `efetch` ≤ 8 MiB, XML с `DOCTYPE`/`ENTITY` отклоняется до разбора, idlist обрезается до `retmax`; FR-36: видимость статьи персональная — врач видит в ответах ассистента только статьи, которые одобрил сам (`kb_work_approvals`), гайдлайны ВОЗ — без решения (docs/15 §12) | LOW — снят для статей: неодобренная врачом публикация не попадает в его выдачу даже после админского approve; остаточный — ревьюер может одобрить мусор сам |
| R15 | Автоматизированная оценка качества принимается за валидированную | AMSTAR 2 по одному абстракту | Ложная уверенность в методологии | 2×3=6 | `experimental=true`, `overall=critically_low` при abstract-only, `manual_review`/`manual_review_reason`, дисклеймер в docs/15 §7 | LOW — оценка не выводится пациенту |
| R16 | Отказ внешнего API останавливает обогащение | сетевой сбой/бан NCBI/IRIS | КБ не пополняется | 2×2=4 | `kb_runs` с `status=failed/partial`, per-document savepoints, таймауты, интервал прогонов, `CC_ENRICH_OFFLINE`; URL IRIS проверяются (`https` + `iris.who.int`, каждый редирект), ответ PubMed ≤ 8 MiB без `DOCTYPE`/`ENTITY`; восстановление индекса — `python -m app.enrichment reindex` | LOW — деградация без влияния на выдачу |
| R17 | Несанкционированный egress в ЕМИАС / уход на чужой хост | включённая интеграция, подмена base URL, redirect | Передача ПДн во внешний контур вне согласия | 2×4=8 | `CC_EMIAS_ENABLED=false` по умолчанию; белый список хостов = netloc `CC_EMIAS_BASE_URL`; redirect запрещён; `CC_EMIAS_ALLOW_INSECURE=true` только для мока; вызовы только ADMIN-триггером | MEDIUM — остаётся доверие к DNS/периметру УЗ-2 |
| R18 | Утечка OAuth-токена/секрета ЕМИАС в логи или БД | отладка, ошибки HTTP, дампы | Доступ к ПДн пациентов контура | 2×4=8 | токен только в памяти процесса (кэш 80% TTL); Authorization и тела не логируются; `client_secret` в env/секретах, не в БД и не в API-ответах (`health` отдаёт только host) | LOW — при компрометации хоста токен живёт ≤ expires_in |
| R19 | ПДн (СНИЛС, назначения, ФИО/телефон из ЕМИАС) в логах/журнале синхронизации | логирование query/body, широкие stats | Нарушение 152-ФЗ ст. 10 (спецкатегория) | 2×4=8 | query не логируется; `emias_sync_runs.stats` — только счётчики/коды; СНИЛС → sha256+перец, raw не хранится; title/dosage препаратов — pgcrypto; аудит `READ_EMIAS` при чтении врачом | LOW — ФИО/телефон ЕМИАС не сохраняются локально |
| R20 | Раскрытие контактов пациента (телефон, дата рождения) через общий экран/плечевой просмотр | Врач открыл карточку на общем мониторе; полный номер в списке пациентов | Идентификация пациента сторонними (ФИО + телефон/ДР) | 2×3=6 | FR-22: в списке и карте только маска `+7•••123-45-67`; полный номер — отдельный endpoint с аудитом `READ_PATIENT_CONTACTS`; телефон в БД — pgcrypto; без активного согласия контакты не отдаются (`CONSENT_REQUIRED`), отзыв согласия обнуляет поля | LOW — маска всё же раскрывает 7 последних цифр; UI-подсказка о приватном экране не реализована |
| R21 | Гейт-вопрос риска и обработка сигнала в ежедневном чек-ине | HR4/RS1–RS3 — собственные формулировки без валидации (нет ASQ/NIMH); ответы приходят домой без наблюдения; пациент может закрыть приложение на модуле RS; сигнал попадает в очередь, но срок реакции не задан | Пропущенный или ложный риск: пациент с намерением не получает помощи, либо ложная тревога перегружает врача | 3×5=15 | docs/16 §3: HR4 обязателен в ядре (частичный шаг → `422`, поэтому «HR4 не заполнен» через API недостижим; `unassessed` — только защитная ветка чтения). HR4 = «Да» → `Escalation(kind=CHECKIN_RISK)` создаётся **сразу**, до RS, вместе с `Notification` ростерным врачам; итоговый `signal` обновляет ту же строку до `CHECKIN_RISK_URGENT` и уведомляет повторно; partial unique index по `checkin_session_id` исключает дубли при повторе/гонке; `notified_clinician_at` — только при реально созданных уведомлениях. Общая очередь `GET /escalations` доступна любому врачу и админу (не только ростерному), аудит `READ_ESCALATIONS`; `clinician_notified` в ответе чек-ина. Пациенту — экран экстренной помощи, без обещания мгновенного контакта | HIGH — технические меры закрывают потерю сигнала, но организационный процесс (ответственные, SLA, рабочие часы, резервный порядок) не назначен (docs/16 §3) |
| R22 | НЯ, о котором сообщил пациент: непроверенное событие принимают за клинический факт; уведомление о серьёзном НЯ раскрывает ПДн | Пациент сообщает о НЯ без врачебной проверки; текст уведомления мог бы включать ФИО/описание | Ложная клиническая картина при проверке; утечка спецкатегории в уведомлении/пуше | 2×4=8 | FR-28: сообщение пациента всегда `status=pending`, в карточке помечено «сообщил пациент», врач подтверждает/отклоняет, фиксируются `verified_by/verified_at`; текст уведомления фиксированный («Пациент сообщил о серьёзном нежелательном явлении») — без ФИО и описания; `event_text`/`verification_note` — pgcrypto; очередь и PATCH roster-гейтятся (чужой пациент → 404 `ADVERSE_NOT_FOUND`), аудит без содержимого | LOW — пациент видит статус без врачебной заметки; срок реакции врача на очередь не регламентирован (демо) |
| R23 | ПДн переписки уходят во внешний LLM при анализе фактов | Включение FR-31 без локальной модели либо неявный внешний провайдер | Передача спецкатегории ПДн за пределы контура (152-ФЗ ст. 10, 12) | 2×5=10 | FR-31 по умолчанию выключен: нужны **оба** условия — `CC_CHAT_INSIGHTS_ENABLED=true` **и** заданный `CC_ASSISTANT_LLM_URL`; иначе `503 CHAT_INSIGHTS_DISABLED`. Рекомендуемый режим — локальная модель в контуре (docs/17, `infra/docker-compose.local-llm.yml`); внешний провайдер — отдельное решение с ДПО/оценкой воздействия. В LLM уходит только деперсонализированная переписка (`scrub_for_llm`: ФИО пациента/врача, телефон, документы, адрес → плейсхолдеры), сообщения обрезаны (≤500 символов, всего ≤6000); результат — черновики `pending`, в карточку попадают только принятые врачом; аудит без текстов | MEDIUM — остаётся доверие к конфигурации `CC_ASSISTANT_LLM_URL` (локальный хост) |
| R24 | Отказ API при перегрузке: исчерпан пул БД или потокового пула | Всплеск запросов ассистента/логинов, фоновые сервисы забрали соединения | Недоступность сервиса вместо деградации; отказ в помощи в момент нагрузки | 2×3=6 | `validate_pool_budget()` на старте считает все процессы (воркеры + фоновые) и падает при неверной конфигурации; фоновые пулы малы (`CC_DB_BG_*`), sync-движок на `NullPool`; исчерпание пула отдаётся как `503 DB_UNAVAILABLE` + `Retry-After`, а не 500 (docs/03 §12). Rate limiter логина — общий счётчик в Redis (`CC_REDIS_URL`, сервис `redis` в compose): `INCR`+`EXPIRE` на ключ фиксированного окна, ключи — SHA-256, TTL = 2 окна, поэтому N воркеров/реплик тратят ОДИН `CC_RATE_MAX` (замер: 5 попыток на 2 процесса → 429 на 6-й; в memory-режиме — только на 11-й). Без Redis, без extra `api[redis]` или при его отказе — memory с WARNING (бюджет умножается на N, fail-open); короткий таймаут не вешает логин |
| R25 | Сырое ФИО, которого нет в ростре, утекает в LLM (regex-путь) | Пациент/врач упоминает третье лицо или ФИО написано не так, как в ростре; `CC_DEPERSONALIZE_NER=off` деградирует до deny-list | Передача спецкатегории ПДн за пределы контура даже при включённой деперсонализации | 3×4=12 | Прод-путь — GPU-sidecar `CC_DEPERSONALIZE_NER=remote` + `CC_ML_URL` (тот же rubert ФИО/адрес + структурные правила + контрольные числа, api без torch) либо локальный `hybrid`. В `CC_PROD_MODE` с настроенным LLM-egress backend обязателен (иначе `Settings()` падает), а недоступность sidecar/модели или сбой инференса даёт `503 DEPERSONALIZATION_UNAVAILABLE` раньше вызова LLM — сырой текст не отправляется (fail-closed). Метрики: clinical corpus 332 контекста, hybrid/remote P 1.000 / R 0.987 (docs/12, `REPORT-pii.md`). Вне prod деградация до regex с логом | Остаточные 2.5% ФИО: запись целиком строчными буквами, NER не размечает; структурная эвристика отключена осознанно |
| R26 | Недоступность ML-сайдкара (GPU-сервис `ml`) во время клинического запроса | Остановка контейнера, OOM/зависание CUDA, загрузка моделей, сбой `mlnet`, пустой том `ml-models` при offline-старте | Задержка ответа до `CC_ML_TIMEOUT` (5 с) + один повтор; при отказе — деградация поиска/реранка к локальному пути, а маскирование ПДн в прод-режиме fail-closed (запрос не уходит) | 2×2=4 | Таймаут и ровно один повтор на сетевой сбой/5xx; 503 `model_loading`/`model_unavailable` + `Retry-After`; `degraded=true` от NER api трактует как отказ backend'а (prod — 503); `restart: unless-stopped`; `/health` с `status`/`device`; api не подменяет результат — `MlUnavailable` обрабатывает вызывающий (docs/03 §12, docs/08 §4.1) | LOW — при недоступном сайдкаре падает качество/доступность, но ПДн не утекают |
| R27 | Текст анамнеза (спецкатегория ПДн) уходит во внешний LLM | Включение FR-37 без локальной модели или неявный внешний провайдер; врач вставляет ФИО/телефон/дату рождения в «краткие вводные» | Передача спецкатегории ПДн за пределы контура (152-ФЗ ст. 10, 12) | 2×4=8 | `CC_ANAMNESIS_ENABLED=false` по умолчанию; черновику дополнительно нужен `CC_ASSISTANT_LLM_URL`. Перед LLM — только `scrub_for_llm` (regex + ML + deny-list ростра и самого пациента/врача); в `CC_PROD_MODE` недоступный ML-backend → `503 DEPERSONALIZATION_UNAVAILABLE` (fail-closed), вне prod — regex-деградация с WARNING. **Локальная LLM (docs/17).** LLM-роутер ассистента получает только очищенный от ПДн запрос (docs/12) и не строит клинический ответ (R11). FR-21: при переформулировке уточняющего вопроса в LLM уходят последние реплики треда, каждая — после `scrub_for_llm` (ФИО из ростра, телефон, дата рождения с маркером, документы, адрес); переформулировка используется только для retrieval/выбора раздела, red line и ответ считаются по исходному вопросу. Для контуров без внешнего egress предусмотрен локальный вариант: `infra/docker-compose.local-llm.yml` поднимает llama.cpp в сети `infra_default`, api обращается к `http://local-llm:8080/v1`; контейнер модели не публикуется наружу (порт только `127.0.0.1`) и не делает исходящих вызовов. Прод-дефолт — `CC_ASSISTANT_LLM_URL` пуст (роутер выключен), поэтому внешняя передача запроса без явного включения не возникает.

**FR-31 — анализ переписки.** Текст переписки — спецкатегория ПДн, поэтому фича выключена по умолчанию и включается только явной парой `CC_CHAT_INSIGHTS_ENABLED=true` + `CC_ASSISTANT_LLM_URL`; при выключенной фиче LLM не вызывается вовсе. Рекомендуемая конфигурация — локальная модель в контуре (docs/17): тогда ПДн не покидают сеть заказчика; внешний OpenAI-совместимый провайдер допустим только как отдельное решение (ДПО, оценка воздействия, договор поручения — 152-ФЗ ст. 6 ч. 3, ст. 12). В промпт уходит только результат `scrub_for_llm` (ФИО пациента и врача из явной deny-list, ростер, телефон/документы/адрес по regex), каждое сообщение ≤500 символов и весь диалог ≤6000; модель возвращает факты, которые сохраняются как `pending` и попадают в карточку только после `accepted` врачом.

**FR-37 — анамнез пациента.** Два пути обработки ПДн: (1) хранение — `brief`/`text` шифруются `EncryptedText` (pgp_sym_encrypt, ключ `CC_DATA_KEY`), доступ только через roster + активное согласие, в карточку `report.anamnesis` попадает только при согласии; (2) egress в LLM — только `POST …/anamnesis/draft`, только после `scrub_for_llm`, и только при включённых `CC_ANAMNESIS_ENABLED=true` и `CC_ASSISTANT_LLM_URL`. Черновик не сохраняется: запись в БД — исключительно через `PUT` после подтверждения врачом. Аудит фиксирует `ANAMNESIS_DRAFT`/`ANAMNESIS_WRITE` с id пациента и актора, без текста; в логах — только тип ошибки LLM и длительность.

```mermaid
graph LR
  Patient[Пациент UI] -->|HTTPS /api| Nginx
  Doctor[Врач UI] -->|HTTPS /api| Nginx
  Nginx -->|proxy| API[FastAPI :8000]

  API -->|hybrid search| Qdrant[(Qdrant KB)]
  ENR[kb-enrichment] -->|esearch/efetch HTTPS| NCBI[NCBI E-utilities]
  ENR -->|DSpace REST HTTPS| IRIS[WHO IRIS]

  PG[(Postgres)] -->|kb_works/kb_runs| ENR
  PG -->|pg_dump| Backup[Backup gz]
```

### 3.1 Граница api ↔ ML-сайдкар

`ml` — отдельный GPU-контейнер в выделенной внутренней сети `mlnet`
(`internal: true`, профиль `gpu`, `http://ml:8080`, порт на хост не
публикуется). В `mlnet` входят только api и ml: postgres/qdrant/redis и
внешний интернет из неё недоступны. По границе ходят только тексты
запросов/пассажей (открытый клинический контент БЗ) и **уже
деперсонализированные/подлежащие маскированию** фрагменты карты; ответы —
векторы, логиты и замаскированный текст со спанами. Свойства границы:

- **Ничего не персистится.** Сайдкар держит запрос/ответ только в памяти
  процесса; нет БД, файлов с текстами и кеша запросов. На диск попадают
  только веса моделей (том `ml-models`).
- **Нет внешнего egress.** У `ml` нет маршрута наружу; веса скачивает
  одноразовый `ml-warmup` (default-сеть, egress только на время прогрева),
  после чего `ml` стартует с `HF_HUB_OFFLINE=1`/`TRANSFORMERS_OFFLINE=1`.
- **Аутентификация.** Общий секрет `CC_ML_TOKEN` в заголовке
  `X-CC-ML-Token`; TLS не используется, т.к. трафик не покидает `mlnet`.
  Пустой токен — только явный `CC_ML_ALLOW_ANONYMOUS=1` (локальная отладка,
  никогда не прод): без токена и без флага приложение не стартует.
- **Логи.** В логи не пишутся тела запросов/ответов и найденные ПДн; ошибки
  валидации не эхоят вход; `/health` и тексты 503 не содержат путей к
  весам/токена (только флаг `error: bool`).

Остаточный риск недоступности — R26.
