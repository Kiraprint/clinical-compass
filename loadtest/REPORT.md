## 5. Выводы

- Предел одного процесса uvicorn без БД: **1 223.6 RPS**.
- Чтение дневника (JWT + PostgreSQL + аудит): **133.7 RPS** — 11 % от предела без БД.
- Запись дневника (шифрование + commit + аудит): **127.5 RPS**.
- Полный скрининг PHQ-9 (3 HTTP-запроса, 9 ответов, запись + аудит): **33.8 транзакций/с**.
- Дефолтный пул (5+10) обрывается при **C≈60**: 71% ошибок, p50 30 085.9 мс (15 соединений висят в `idle in transaction`).
- С пулом 80 тот же сценарий держит **C=96** без ошибок при 117.7 RPS — обрыв снимается размером пула, но не пропускной способностью БД.
- RAG-ответ врачу (Qdrant + аудит, детерминированная сборка): **65.4 RPS**; время ответа p50 424.2 / p95 926.1 мс на C=32.
- Роспись врача: **44.2 RPS**, p50 1 027.6 мс — N+1 в `clinician.list_patients` (3 запроса на пациента).
- Накладные расходы агента над чистым поиском: 22.7 мс на запрос (p50 5.6 → 28.3 мс).
- ML (hash-эмбеддер): Recall@3 0.382 → 0.400, nDCG@3 0.355 → 0.364, MRR@3 0.424 → 0.430 (прямой поиск → агент).
- Red line: 5/6 отказов на запросы диагноза/назначения (83%).
- **Red line пропускает**: Сколько мг эсциталопрама принимать? — формулировка без глагола назначения/диагноза не матчится `detect_redline`.
- `build_corpus` при промахе лексического гейта: 642 вызовов в секунду (p50 1.03 мс) — выполняется на каждый запрос агента, где поиск вернул меньше `limit` фрагментов.

## 6. Ограничения

- Один процесс API, без nginx/TLS и без внешнего LLM.
- Postgres и Qdrant — локально в Docker; межсерверная сеть не моделируется.
- Эмбеддер `hash` — демо-база; прод-качество поиска см. `bench/README.md` (bge-m3: nDCG@10 0.815 на тех же 55 запросах).
- Замкнутый контур: p95 на высоких C включает очередь к пулу БД (SQLAlchemy: 5 + 10 overflow).
