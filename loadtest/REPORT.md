## 5. Выводы

- Предел одного процесса uvicorn без БД: **975.2 RPS**.
- Чтение дневника (JWT + PostgreSQL + аудит): **166.2 RPS** — 17 % от предела без БД.
- Запись дневника (шифрование + commit + аудит): **260.6 RPS**.
- Полный скрининг PHQ-9 (3 HTTP-запроса, 9 ответов, запись + аудит): **42.2 транзакций/с**.
- Async-пул по умолчанию (40 соединений) держит **C=128** без ошибок при 187.5 RPS (p50 531.4 мс).
- С пулом 80 соединений тот же сценарий держит **C=64** без ошибок при 191.6 RPS.
- Ошибки на пуле 80 при C=96 — упор в `max_connections=100` Postgres (пул 80+20 не оставляет запаса), а не дефект приложения.
- RAG-ответ врачу (Qdrant + аудит, детерминированная сборка): **92.1 RPS**; время ответа p50 155.8 / p95 295.7 мс на C=16.
- Роспись врача: **265.2 RPS**, p50 165.3 мс — батчинг из 4 запросов на весь список (было 1+3N запросов на пациента).
- Накладные расходы агента над чистым поиском: 20.0 мс на запрос (p50 3.4 → 23.4 мс).
- ML (hash-эмбеддер): Recall@3 0.382 → 0.382, nDCG@3 0.355 → 0.349, MRR@3 0.424 → 0.418 (прямой поиск → агент).
- Red line: 6/6 отказов на запросы диагноза/назначения (100%).
- `build_corpus` (кеш статических секций): 1 857 750 вызовов в секунду (p50 0.5 мкс); на request-path препараты приходят из async-сессии, без повторного запроса к БД.

## 6. Ограничения

- Один процесс API, без nginx/TLS и без внешнего LLM; `WEB_CONCURRENCY` поддержан, но в этом прогоне не измерялся.
- Postgres и Qdrant — локально в Docker; межсерверная сеть не моделируется.
- Эмбеддер `hash` — демо-база; bge-m3 включается `CC_EMBEDDER=bge-m3` с extra `embeddings` и переиндексацией KB.
- Замкнутый контур: p95 на высоких C включает очередь к async-пулу БД (SQLAlchemy: 20 + 20 overflow на процесс).
