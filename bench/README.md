# Бенчмарк качества поиска (эмбеддеры для RU-EN психиатрии)

Оценка, **какой эмбеддер лучше для русско-английских клинических документов по
тревоге/депрессии** (база знаний ИИ-агента). Запускается **отдельно** от API/демо —
не входит в docker-образы, требует сети и тяжёлых моделей.

## Что измеряем

Гибридный поиск (dense + sparse, слияние **RRF**) по корпусу:
- **8 мета-анализов/систематических обзоров** из PMC по тревоге/депрессии
  (MCT vs CBT при ГАД, remote-CBT, dCBT при хронической боли, австралийские DMHS,
  куркумин, цифровые интервенции в онкологии, тай-чи, аэробные нагрузки при БДР);
- **факт-листы ВОЗ** «Depressive disorder» (EN) и «Anxiety disorders» (EN + RU).

108 чанков, **14 золотых запросов** (EN + RU, вкл. кросс-языковые RU-запросы к
EN-источникам). Метрики: **Recall@1/5/10, nDCG@10, MRR@10**.

## Запуск

```bash
# отдельный venv (не тянем тяжёлые модели в проект/API)
~/.local/bin/python3.12 -m venv .venv
.venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install sentence-transformers FlagEmbedding

# сбор источников (PMC E-utilities + факт-листы ВОЗ; сырьё в git не коммитим —
# сторонний контент, см. docs/08 §2; результат в bench/sources/*.json)
.venv/bin/python fetch_sources.py

# сборка корпуса (108 чанков, 14 запросов)
.venv/bin/python build_dataset.py

# прогон всех моделей или одной
.venv/bin/python run_bench.py --all
.venv/bin/python run_bench.py --model bge-m3
```

Модели тянутся с HF при первом запуске (bge-m3 ≈ 2.3 ГБ; CPU считает 108 чанков
≈ минуты, bge-m3 ≈ 6 мин).

## Результат (CPU, nDCG@10; плотности: dense / dense+sparse RRF / dense+BM25 RRF)

| Модель | dense | hybrid (RRF) | +BM25 | R@10(dense) | MRR(dense) |
|---|---|---|---|---|---|
| hash (офлайн-база) | 0.329 | 0.377 | 0.413 | 0.429 | 0.404 |
| deepvk/USER-bge-m3 | 0.736 | 0.578 | — | 0.917 | 0.792 |
| ai-forever/FRIDA | 0.697 | 0.566 | — | 0.810 | 0.798 |
| **BAAI/bge-m3** | 0.742 | 0.587 | 0.699 | 0.714 | 0.667 |
| Qwen/Qwen3-Embedding-0.6B | 0.798 | 0.608 | 0.677 | 0.750 | 0.705 |
| intfloat/multilingual-e5-large | **0.820** | 0.581 | 0.651 | 0.952 | 0.845 |

Погонять одну плоскость: `run_bench.py --model e5-multilingual:dense`,
`--model bge-m3:bm25`, `--variant dense`. Попарный разбор e5 vs bge:
`pairwise.py` (6 побед, 6 ничьих, 2 поражения e5 из 14 запросов).

## Пропускная способность (измерено)

- **Живой API** (`/assistant/ask`, hash-эмбеддер, локальный стек): **37.7 RPS**,
  p50=26 мс, p95=39 мс (60 последовательных запросов).
- **bge-m3, CPU (fp32)**: 2.97 с на запрос → **0.34 q/s** (непригоден онлайн).
- **bge-m3, GPU (RTX 5090, fp16)**: запрос p50=15 мс → **66 q/s**;
  батч 8 → 244 q/s; батч 32 → **779 q/s**. Индексация: **2800 док/с** (~8k
  чанков за ~3 с).
- Qdrant (8 точек): p50=2 мс, p95=12 мс — не узкое место.

Вывод: нейросетевой эмбеддер в проде **обязательно на GPU**, иначе латентность
запроса растёт с 26 мс до секунд; батч-инференс даёт ~10-кратный запас.

## Честные ограничения (обязательно к прочтению)

1. **Выборка крошечная** (14 запросов). Разница e5 vs bge-m3 по dense (0.078
   nDCG) на 6 победах/2 поражениях из 14 — направленный, но не статистически
   уверенный сигнал; нужна расширенная выборка запросов.
2. **На этом корпусе dense-only обгоняет гибрид у всех кандидатов** — RRF с
   любым спарс-каналом (настоящие веса bge-m3, BM25, хеш) не помогает на 108
   чанках. Это вывод бенчмарка, не прод: на большом корпусе гибрид может
   окупиться.
3. **dense-only кандидаты получают слабый sparse-хеш** (не BM25) в плоскости
   hybrid; для чистой оценки dense используйте `:dense`. bge-m3 использует
   **настоящий** sparse — один encoder → 3 вектора под Qdrant.
4. Qwen3 требует **инструкционного префикса** запроса; generic-префикс на этой
   выборке дал 0.592 (< без него 0.798) — префикс не подогнан, поэтому такие
   числа ни «за», ни «против».
5. Корпус собран из **открытых** источников (PMC OA, факт-листы ВОЗ); полные
   тексты КР Минздрава не заливаются (см. docs/08 §2 про копирайт).

## Вывод (см. docs/07 §5, docs/08 §4)

Рабочая модель прода — **BAAI/bge-m3**: единственный даёт **настоящие dense+sparse**
(и colbert) одной моделью, 100+ языков, MIT, self-host. Подключается через
`CC_EMBEDDER=bge-m3` (SPI `build_embedder()`); по умолчанию остаётся офлайн
`hash` для демо/тестов. Если качество станет приоритетом — e5-multilingual
(dense-only) на этой выборке лучший (0.820 nDCG@10), но для прод-гибрида
потребует отдельного лексического канала (BM25/FTS); решение — по расширенной
выборке запросов.
