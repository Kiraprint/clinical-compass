# Бенчмарк качества поиска (эмбеддеры для RU-EN психиатрии)

Оценка, **какой эмбеддер лучше для русско-английских клинических документов по
тревоге/депрессии** (база знаний ИИ-агента). Запускается **отдельно** от API/демо —
не входит в docker-образы, требует сети и тяжёлых моделей.

## Что измеряем

Гибридный поиск (dense + sparse, слияние **RRF**) по корпусу:
- **8 мета-анализов/систематических обзоров** из PMC по тревоге/депрессии
  (MCT vs CBT при ГАД, remote-CBT, dCBT при хронической боли, австралийские DMHS,
  куркумин, цифровые интервенции в онкологии, тай-чи, аэробные нагрузки при БДР);
- **факт-листы ВОЗ** «Depressive disorder» (EN) и «Anxiety disorders» (EN + RU).

108 чанков, **14 золотых запросов** (EN + RU, вкл. кросс-языковые RU-запросы к
EN-источникам). Метрики: **Recall@1/5/10, nDCG@10, MRR@10**.

## Запуск

```bash
# отдельный venv (не тянем тяжёлые модели в проект/API)
~/.local/bin/python3.12 -m venv .venv
.venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install sentence-transformers FlagEmbedding

# сбор источников (PMC E-utilities + факт-листы ВОЗ; сырьё в git не коммитим —
# сторонний контент, см. docs/08 §2; результат в bench/sources/*.json)
.venv/bin/python fetch_sources.py

# сборка корпуса (108 чанков, 14 запросов)
.venv/bin/python build_dataset.py

# прогон всех моделей или одной
.venv/bin/python run_bench.py --all
.venv/bin/python run_bench.py --model bge-m3
```

Модели тянутся с HF при первом запуске (bge-m3 ≈ 2.3 ГБ; CPU считает 108 чанков
≈ минуты, bge-m3 ≈ 6 мин).

| Модель | R@1 | R@5 | R@10 | nDCG@10 | MRR |
|---|---|---|---|---|---|
| hash (офлайн-база) | 0.107 | 0.357 | 0.452 | 0.363 | 0.446 |
| deepvk/USER-bge-m3 | 0.190 | 0.655 | 0.690 | 0.582 | 0.681 |
| ai-forever/FRIDA | 0.190 | 0.583 | 0.655 | 0.554 | 0.661 |

## Честные ограничения (обязательно к прочтению)

1. **Выборка крошечная** (14 запросов). Разница nDCG «Qwen3 vs bge-m3» ≈ 0.03 —
   в пределах шума, **не** основание для смены модели.
2. **dense-only кандидаты получают слабый sparse-хеш** (не BM25). Их цифры
   оптимистичны: в продакшн-конфигурации у них sparse-канал нужно строить
   отдельно (BM25/FTS), чего в бенчмарке нет. bge-m3 использует **настоящий**
   sparse — это его главный козырь (один encoder → 3 вектора под Qdrant).
3. Qwen3 требует **инструкционного префикса** запроса; generic-префикс на этой
   выборке дал 0.592 (< без него 0.624) — префикс не подогнан под предметную
   область, поэтому такие числа нельзя считать ни «за», ни «против».
4. Корпус собран из **открытых** источников (PMC OA, факт-листы ВОЗ); полные
   тексты КР Минздрава не заливаются (см. docs/08 §2 про копирайт).

## Вывод (см. docs/07 §5, docs/08 §4)

Рабочая модель прода — **BAAI/bge-m3**: единственный даёт **настоящие dense+sparse**
(и colbert) одной моделью, 100+ языков, MIT, self-host. Подключается через
`CC_EMBEDDER=bge-m3` (SPI `build_embedder()`); по умолчанию остаётся офлайн
`hash` для демо/тестов. Qwen3-Embedding-0.6B / e5 — запасной вариант при замене
sparse на BM25/FTS.
