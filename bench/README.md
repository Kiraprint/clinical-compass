# Бенчмарк качества поиска (эмбеддеры для RU-EN психиатрии)

Оценка, **какой эмбеддер лучше для русско-английских клинических документов по
тревоге/депрессии** (база знаний ИИ-агента). Запускается **отдельно** от API/демо —
не входит в docker-образы, требует сети и тяжёлых моделей.

## Что измеряем

Гибридный поиск (dense + sparse, слияние **RRF**) по корпусу:
- **8 мета-анализов/систематических обзоров** из PMC по тревоге/депрессии
  (MCT vs CBT при ГАД, remote-CBT, dCBT при хронической боли, австралийские DMHS,
  куркумин, цифровые интервенции в онкологии, тай-чи, аэробные нагрузки при БДР);
- **факт-листы ВОЗ** «Depressive disorder» (EN) и «Anxiety disorders» (EN + RU).

108 чанков, **14 золотых запросов** (EN + RU, вкл. кросс-языковые RU-запросы к
EN-источникам). Метрики: **Recall@1/5/10, nDCG@10, MRR@10**.

## Запуск

```bash
# отдельный venv (не тянем тяжёлые модели в проект/API)
~/.local/bin/python3.12 -m venv .venv
.venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install sentence-transformers FlagEmbedding

# сбор источников (PMC E-utilities + факт-листы ВОЗ; сырьё в git не коммитим —
# сторонний контент, см. docs/08 §2; результат в bench/sources/*.json)
.venv/bin/python fetch_sources.py

# сборка корпуса (108 чанков, 14 запросов)
.venv/bin/python build_dataset.py
# расширение золотого набора до 55 запросов (RU+EN) с qrels
.venv/bin/python expand_queries.py

# прогон всех моделей или одной
.venv/bin/python run_bench.py --all
.venv/bin/python run_bench.py --model bge-m3:all   # dense+hybrid+bm25 за одну загрузку
.venv/bin/python run_bench.py --model bge-m3

# статистика e5 vs bge-m3 (per-query nDCG, bootstrap-CI, Wilcoxon)
.venv/bin/python significance.py
```

Модели тянутся с HF при первом запуске (bge-m3 ≈ 2.3 ГБ; GPU считает 108 чанков
за секунды, CPU — минуты).

## Замер на прикладном пути API (`eval_app_path.py`)

`run_bench.py` — упрощённый harness (свой косинусный поиск). `eval_app_path.py`
меряет **реальную логику приложения**: индексация через
`app.services.kb.upsert_documents`, поиск через `app.services.kb.hybrid_search`
(NamedVector dense+sparse → prefetch/RRF либо dense-only, как в проде) в
изолированной коллекции Qdrant. Метрики: **RU/EN nDCG@3 и Recall@3** (целевые
для русскоязычного поиска), nDCG@10/MRR@10, латентность p50/p95, время
индексации и память модели.

```bash
# env: torch + FlagEmbedding + sentence-transformers + qdrant-client
python bench/eval_app_path.py --profile hash    --collection kb_eval_hash
python bench/eval_app_path.py --profile bge-m3  --collection kb_eval_bge \
    --json-out bench/data/eval_app_bge_m3.json
python bench/eval_app_path.py --profile e5      --collection kb_eval_e5     # альтернатива
python bench/eval_app_path.py --profile frida   --collection kb_eval_frida  # альтернатива
```

Коллекция пересоздаётся на каждый прогон; `kb`/`kb_test` использовать нельзя.
Результат (55 запросов, 108 чанков, RTX 5090, fp16; hash — RRF, нейросетевые —
dense-only, как в проде):

| Профиль | RU nDCG@3 | RU R@3 | EN nDCG@3 | EN R@3 | all nDCG@10 | p50/p95, мс | Индексация | RAM/VRAM |
|---|---|---|---|---|---|---|---|---|
| hash | 0.142 | 0.139 | 0.413 | 0.450 | 0.434 | 6/8 | 0.5 с | 0.9 ГБ / — |
| **bge-m3** | **0.776** | **0.819** | 0.723 | 0.787 | 0.815 | 49/92 | 4.4 с | 4.6 ГБ / 1.1 ГБ |
| e5-large | 0.616 | 0.611 | 0.739 | 0.860 | 0.788 | 17/37 | 4.5 с | 3.6 ГБ / 2.2 ГБ |
| FRIDA | 0.635 | 0.653 | 0.710 | 0.775 | 0.788 | 47/74 | 23.6 с | 4.3 ГБ / 3.2 ГБ |

Вывод: RU-качество на прод-пути растёт в 5.5x (nDCG@3 0.142 → 0.776). bge-m3 —
прод-профиль (`CC_EMBEDDER=bge-m3`, extra `embeddings`), **с переиндексацией
коллекции** (dense 512 → 1024, docs/08 §4).

## Результат (55 запросов, nDCG@10; плотности: dense / dense+sparse RRF / dense+BM25 RRF)

| Модель | dense | hybrid (RRF) | +BM25 | R@1(dense) | R@5(dense) | R@10(dense) | MRR(dense) |
|---|---|---|---|---|---|---|---|
| hash (офлайн-база) | 0.417 | 0.471 | 0.512 | 0.173 | 0.427 | 0.573 | 0.437 |
| deepvk/USER-bge-m3 | 0.809 | 0.665 | 0.755 | 0.436 | 0.873 | 0.955 | 0.806 |
| ai-forever/FRIDA | 0.789 | 0.653 | 0.724 | 0.409 | 0.861 | 0.952 | 0.793 |
| **BAAI/bge-m3** | **0.815** | 0.722 | 0.737 | **0.427** | **0.897** | 0.964 | **0.804** |
| Qwen/Qwen3-Embedding-0.6B | 0.790 | 0.658 | 0.724 | 0.373 | 0.879 | **0.967** | 0.756 |
| intfloat/multilingual-e5-large | 0.788 | 0.625 | 0.684 | 0.345 | 0.867 | 0.973 | 0.753 |

Набор расширен с 14 до 55 запросов (`expand_queries.py`), потому что на 14
запросах лидировал e5 (0.820 vs 0.742) — на выборке в 4 раза больше
**ранжирование перевернулось**: bge-m3 dense 0.815, user-bge-m3 0.809, qwen3
0.790, e5 0.788. Разница e5↔bge-m3 по nDCG@10 не значима (Wilcoxon p=0.21,
bootstrap-CI [−0.069,+0.019]), но **R@1 у bge-m3 значимо выше** (0.427 vs 0.345,
CI [−0.164,−0.009]).

Плоскости: `run_bench.py --model e5-multilingual:dense|bm25`, `--model bge-m3:all`,
`--variant dense`. Попарная статистика: `significance.py`.


## Пропускная способность (измерено)

- **Живой API** (`/assistant/ask`, hash-эмбеддер, локальный стек): **37.7 RPS**,
  p50=26 мс, p95=39 мс (60 последовательных запросов).
- **bge-m3, CPU (fp32)**: 2.97 с на запрос → **0.34 q/s** (непригоден онлайн).
- **bge-m3, GPU (RTX 5090, fp16)**: запрос p50=15 мс → **66 q/s**;
  батч 8 → 244 q/s; батч 32 → **779 q/s**. Индексация: **2800 док/с** (~8k
  чанков за ~3 с).
- Qdrant (8 точек): p50=2 мс, p95=12 мс — не узкое место.

Вывод: нейросетевой эмбеддер в проде **обязательно на GPU**, иначе латентность
запроса растёт с 26 мс до секунд; батч-инференс даёт ~10-кратный запас.

## Честные ограничения (обязательно к прочтению)

1. **Выборка выросла до 55 запросов**, и это изменило вывод: на 14 запросах
   лидировал e5 (0.820 vs 0.742), на 55 — bge-m3 (0.815 vs 0.788). Урок: 14
   запросов непредставительны. Остаётся оговорка: разница e5↔bge по nDCG@10
   не значима (p=0.21); значим только разрыв по R@1 (0.427 vs 0.345).
2. **На этом корпусе dense-only обгоняет гибрид у всех кандидатов** — RRF с
   любым спарс-каналом (настоящие веса bge-m3, BM25, хеш) не помогает на 108
   чанках. Это вывод бенчмарка, не прод: на большом корпусе гибрид может
   окупиться. BM25+RRF реализован в харнессе (`:bm25`) и именно он даёт
   лексический канал без отдельной нейромодели — то, что просил заказчик.
3. **dense-only кандидаты получают слабый sparse-хеш** (не BM25) в плоскости
   hybrid; для чистой оценки dense используйте `:dense`, для честного
   лексического канала — `:bm25`. bge-m3 использует **настоящий** sparse —
   один encoder → 3 вектора под Qdrant.
4. Qwen3 требует **инструкционного префикса** запроса; generic-префикс на этой
   выборке дал 0.592 (< без него 0.798) — префикс не подогнан, поэтому такие
   числа ни «за», ни «против».
5. Корпус собран из **открытых** источников (PMC OA, факт-листы ВОЗ); полные
   тексты КР Минздрава не заливаются (см. docs/08 §2 про копирайт).

## Вывод (см. docs/07 §5, docs/08 §4)

Рабочая модель прода — **BAAI/bge-m3**: на расширенной выборке (55 запросов)
лучшая по dense nDCG@10 (0.815), R@1 (0.427, значимо выше e5), R@5 (0.897) и
MRR (0.804), **и** единственный даёт настоящие dense+sparse (и colbert) одной
моделью, 100+ языков, MIT, self-host. Подключается через `CC_EMBEDDER=bge-m3`
(SPI `build_embedder()`); по умолчанию остаётся офлайн `hash` для демо/тестов.
Если бы гибрид оказался нужен, лексический канал можно взять и внешним
BM25+RRF (`:bm25` реализован и измерен), но на 108 чанках dense-only лучше.
