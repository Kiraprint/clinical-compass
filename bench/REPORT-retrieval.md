# Отчёт: качество поиска по базе знаний (retrieval quality)

Дата: 2026-10-24. Ветка `feat/retrieval-quality` (worktree `.worktrees/retrieval-research`).
Цель: **строгий top-3 hit ≥ 0.90 и nDCG@3 ≥ 0.90** на документированном
бенчмарке клинической БЗ (RU-запросы врача, EN-корпус ВОЗ).

## 1. Что измеряется

Путь `AgentFactory.search_kb` — тот же, что обслуживает `/assistant/ask` и
сообщения тредов:

```
запрос (+ LLM-переформулировка уточнения, FR-21)
  → эмбеддер профиля (CC_EMBEDDER)
  → Qdrant: dense / dense+sparse → RrfQuery(k)     [CC_RRF_K, CC_RETRIEVAL_CANDIDATES]
  → кросс-энкодерный реранк пула                    [CC_RERANKER]
  → порог «нет релевантного ответа» по профилю      [CC_KB_MIN_SCORE / default]
  → top-5 чанков с цитатами
```

Метрики: **strict top-3 hit** (доля запросов, у которых в top-3 есть чанк
grade = 2 — продуктовый смысл цели 90 %), nDCG@3/5/10 (градуированные gains
2^g−1), Recall@3/5/10 (relevant = grade ≥ 1), Recall@3 по grade = 2,
MRR@10; латентность p50/p95/p99 на запрос (поиск + реранк, без LLM-ответа) и
VRAM после загрузки модели.

## 2. Данные и золотой набор

**Корпус** — снимок прод-коллекции Qdrant `kb` (998 чанков): 978 чанков
руководств ВОЗ (mhGAP, подростки, психическое здоровье на работе, физическое
здоровье при тяжёлых психических расстройствах, фармакологическое лечение;
чанки по 1800 знаков), 7 шкал, 6 карточек препаратов, 2 записи триажа,
5 карточек научных статей. Метрические заголовки русские, тело руководств —
английское: RU→EN кросс-языковой поиск и есть основной сценарий.

**Запросы** — 158 (92 RU + 66 EN): 30 ручных по «хрупким» разделам (устройство
шкал, дозирование и противопоказания, триаж/red line, коморбидность, check-in,
статьи) + 128 сгенерированных по случайным чанкам руководств (детерминизм:
`random.Random(20261024)`, промпт в `bench/build_kb_bench.py`; на чанк — один
естественный RU-вопрос и один EN, без копирования формулировок).

**Разметка** — градуированная 0/1/2, **локальный судья** `Qwen/Qwen3-4B-Instruct-2507`
на GPU (`bench/grade_local.py`, батчи по 20 кандидатов, `do_sample=False`,
дозапись по запросу — прогон возобновляем). Рубрика:

- **2** — фрагмент прямо отвечает на запрос: содержит нужный факт (число
  пунктов шкалы, дозу, критерий, правило red line, рекомендацию);
- **1** — по теме, полезный контекст, но прямого ответа нет;
- **0** — не по теме. Язык не важен (EN-фрагмент может отвечать на RU-вопрос).

Размечается **пул кандидатов**, а не выдача одной модели: объединение top-20
восьми стеков — 11 733 пары, ~74 чанка на запрос. Один и тот же судья и один
и тот же qrels используются для всех стеков. Чанк вне пула считается
нерелевантным (стандартное ограничение pooled-разметки). Золотой набор
коммитится (`bench/data/qrels.jsonl`), выгрузка для человеческой проверки —
`bench/data/kb_qrels_review.tsv` (qid, grade, chunk_id, источник, сниппет, запрос).

**Анти-предвзятость** (`bench/qa_qrels.py`, детерминированные проверки):
у каждого запроса есть chunk с grade = 2 и с grade ≥ 1; средняя доля нулей в
пуле 0.45; дословного зеркалирования запроса и чанка нет (максимальная общая
подпоследовательность слов 5 < 8, средний Jaccard 0.022); у RU-запросов
grade-2 чанки на 96 % латиница — то есть поиск проверяет перевод смысла, а не
совпадение слов.

## 3. Методика замера

1. `bench/eval_retrieval.py` — матрица in-memory: корпус векторизуется один раз
   на модель (кэш `bench/data/cache/`), далее по стекам считаются ранжирования,
   метрики, латентность и VRAM. Один процесс на группу моделей: веса не
   выгружаются, поэтому qwen3-4b (15.5 ГБ) замеряется отдельным запуском.
2. `bench/eval_prod_path.py` — валидация победителя на реальном пути:
   `kb.upsert_documents` в отдельную коллекцию Qdrant + `kb.hybrid_search`
   (Qdrant RRF + `app.services.reranker` + порог профиля).
3. `bench/report_table.py` — пересчёт таблицы по сохранённым ранжированиям.
4. `bench/run_retrieval_suite.sh` — вся цепочка (разметка → QA → матрица →
   таблица) одной командой.
5. GPU: RTX 5090 Laptop 24 ГБ, bf16.

## 4. Стеки

Эмбеддеры: `hash` (что в проде сегодня), `BAAI/bge-m3` (dense; dense+sparse RRF
со свипом k = 10/30/60/100; +ColBERT-рескоринг), `deepvk/USER-bge-m3`,
`intfloat/multilingual-e5-large-instruct`, `Qwen/Qwen3-Embedding-0.6B` и `-4B`,
`ai-forever/FRIDA`.
Реранкеры на топ-2 эмбеддерах (bge-m3, qwen3-0.6b), глубина пула 20/50/100:
`BAAI/bge-reranker-v2-m3`, `jinaai/jina-reranker-v2-base-multilingual`,
`Qwen/Qwen3-Reranker-0.6B`; плюс `DiTy/cross-encoder-russian-msmarco` на bge-m3.

## 7. CPU и форма деплоя (прод — без GPU)

Прод-образ API — CPU-only (`api:latest` ≈ 876 МБ, torch не входит). Замер
`bench/cpu_latency.py` при `OMP_NUM_THREADS=4`:

| модель | embed запроса p50 | p95 | rerank 20 кандидатов | rerank 50 кандидатов |
|---|---|---|---|---|
| bge-m3 | 75 мс | 130 мс | — | — |
| e5-large-instruct | 87 мс | 125 мс | — | — |
| user-bge-m3 | 90 мс | 127 мс | — | — |
| qwen3-0.6b | 111 мс | 152 мс | — | — |
| FRIDA | 419 мс | 528 мс | — | — |
| bge-reranker-v2-m3 | — | — | 11.9 с | 28–31 с |

Даже эмбеддинг запроса на CPU съедает весь бюджет `/assistant/ask`
(p95 ≈ 120 мс) до похода в Qdrant, а проход кросс-энкодера по 20 кандидатам —
~12 с. Стоимость образа при установке torch: CPU-wheel `torch` 176 МБ сжатого /
682 МБ распакованного, `transformers` ~40 МБ, `sentence-transformers` ~5 МБ,
hub/tokenizers ~20 МБ → **≈ +0.9 ГБ к распакованному образу** (CUDA-wheels в
образ не ставятся никогда). Итог: нейросетевой профиль в CPU-контейнере
непригоден; рекомендуемая форма — host-side GPU-сервис эмбеддинга/реранка за
`CC_EMBEDDER_URL` (docs/08 §4.6), API-образ остаётся без torch.

## 8. Ограничения

- Pooled-разметка: чанк вне пула — нерелевантен; все замеряемые стеки в пуле.
- Судья — LLM (Qwen3-4B-Instruct), не человек: выгрузка для выборочной
  проверки приложена; отдельные спорные grade-1/0 в клинических нюансах возможны.
- Латентность — без LLM-ответа и без сетевого хопа Qdrant (in-memory матрица);
  прод-путь меряется отдельным скриптом.
- ColBERT — рескоринг пула на CPU, не оптимизирован.
- qwen3-4b помещается в 24 ГБ только отдельным процессом (15.5 ГБ VRAM).

bash bench/run_retrieval_suite.sh --matrix     # только матрица (qrels уже есть)
